Subscription Agent Control Plane Research

Current as of 2026-07-03. This report researches a Chief Moa control plane for subscription/account credentials, browser sessions, chat-history recovery, and bounded agent fanout.

Bottom line: no single product solves the whole system. Build Chief Moa's own control plane and use Nango-style OAuth brokerage, Playwright/browser contexts, CH/common-chat import, CASS-style retrieval, and DBOS-style durable Postgres workflows as the first stack.

Recommended Stack

Search designCASS and CallimachusBM25, vector search, cited snippets, bounded evidence packs.

Local History Inventory

CH detects 3,935 local sessions: 2,391 OpenCode, 1,132 Codex, 283 Claude Code, and 129 Gemini sessions. This confirms the need for indexing, dedupe, candidate-task extraction, and promotion gates before any agent fanout.

Control Plane Primitives

account_connection

Provider connection, broker ref, scopes, health, expiry, reauth URL, revocation state.

browser_session

Encrypted browser profile/context ref, lease owner, TTL, allowed domains, user takeover.

candidate_task

Extracted task with citations, duplicate group, risk, and promotion state.

work_node

Canonical unit of progress with agent runs, artifacts, verification, and receipts.

Boundary

Agents may request capabilities. They do not receive raw credentials. External account creation, MFA, CAPTCHA, payment, deploys, and policy-sensitive actions require explicit human approval and receipts.
