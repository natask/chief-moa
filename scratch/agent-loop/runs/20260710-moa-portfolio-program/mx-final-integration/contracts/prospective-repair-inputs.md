# Prospective MX repair-contract inputs

These are contractor inputs, not permission for MX to implement feature code.

## M3 integration contract input

- Base only on the independently audited candidate commit.
- Rerun focused artifact/scope/preflight tests, quality/complexity gate,
  interruption/fork/invalidation smokes and both relevant strict OpenSpecs.
- Merge auditor enumerates voice, cascaded reasoner, broker, session-history,
  thread-enrichment, incognito and branch-switch entry points.
- Block on retrieval before privacy decision, cross-tenant/branch/deleted source,
  misleading receipt/source counts, cache identity omission, secret leakage,
  unbounded traversal, or duplicated ranking authority.
- After cherry-pick, rerun full gateway and context specifications on staging.

## M5 protocol integration contract input

- Candidate must pass `openspec validate define-aggie-compatible-surface --strict`.
- Reject unknown/additive credential-shaped fields recursively.
- Bind approval/receipt to full surface authority: kind, mode, device identity,
  protocol version, proposal/action identity and relevant state/freshness.
- Prove stale, replay, cross-device, cross-surface and N/N-1 cases.
- Rerun Android/browser regressions after protocol integration; no native shell
  may fork or reinterpret the canonical protocol.

## M6 hosted-boundary repair input

- Inventory every existing companion create/preview/apply/profile route.
- Define one explicit transition from verified immutable package to a bounded
  local apply proposal; no package verifier result directly mutates a profile.
- Require trusted tenant, trust-root snapshot, license/moderation decision,
  revocation freshness, compatibility and reversible receipt.
- Public publication remains blocked until business/legal authority exists.

## Migration/restore evidence contract input

- Use a disposable database and non-production principals.
- Prove up migration, old-code/new-schema compatibility, application-role RLS,
  two-principal isolation, concurrent budget reservation, backup, scratch
  restore, and idempotent rerun.
- No production `DATABASE_URL`, destructive rollback, or active data mutation.

## Native serial program inputs

For macOS, then iOS, then Windows: exact owned files/worktree, protocol version,
permission and secure-token model, local approval/receipt authority, bounded
offline/reconnect behavior, signing/update/rollback plan, accessibility gate,
platform build, isolated signed update, and physical-device evidence. One OS is
never evidence for another.

## Promotion evidence contract input

Require all of the following for the exact final commit/artifact digest:

1. separate URL and separate database, queue, storage path and worker pool;
2. fresh combined verification and preview smoke;
3. old/new persisted-state compatibility;
4. no active recording, turn, upload, run, job or session is stranded, with
   drain/resume/retry proof;
5. backup plus scratch restore;
6. known fast rollback to the previous artifact/ref/config/state;
7. guarded apply receipt and post-apply smoke.

Any missing item stops at a committed artifact and records the blocker.
