# Goal: M6 companion catalog, sharing and provenance

Compile and execute M6 from `../portfolio-managers.md`,
`../intent-execution-map.md`, companion OpenSpecs, parent instructions and prior
profile/customization notes. Own branch/worktree
`agent/m6-companion-catalog-sharing` /
`chief-moa-worktrees/m6-companion-catalog-sharing`. Companions remain bounded
data/assets: no JS, CSS, shell, eval or undeclared profile mutation.

Begin parallel read-only passes for existing manifest/profile topology;
signature/trust-root and revocation design; archive/image/resource attacks;
provenance/license/moderation policy; compatibility and client UX gates; and
current official cryptographic/package facts. Use a strong package/security
model for the contract, narrow UI executors only after API freeze, and fresh
supply-chain/resource/trust/UX auditors. Model reputation is not evidence.

The contract must own exact manifest/version/hash/signature/provenance/license/
compatibility/revocation fields; streaming size/count/dimension bounds;
content-addressed dedupe; preview/apply/revert receipts; pagination; migration
and rollback; complexity <=10/CRAP <=15 and resource budgets. Disjoint slices
may cover package crypto, backend policy and post-freeze UI.

Gates: strict companion specs; tamper/unknown-signer/revocation fixtures;
archive/resource fuzz; provenance completeness; compatibility; publish/install/
preview/apply/revert; tenant/privacy isolation; and touched-surface gates. Block
executable payloads, unsigned/unlicensed artifacts, cosmetic revocation, bombs,
moderation bypass or privacy leaks. Hosted sharing waits for MF identity and MX
protocol gates. Public trust root, accepted licenses and moderation/appeal
policy are parent blockers, so local verification may proceed but marketplace
readiness may not be claimed.

Separate command-backed measured results from architecture-confidence targets
and list offline revocation, public moderation and real-client unknowns.
