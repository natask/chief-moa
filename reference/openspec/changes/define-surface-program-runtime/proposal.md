# Define Surface Program Runtime

## Why

Moa needs more than a growing list of one-operation tools. An agent should be
able to compose browser work as JavaScript/TypeScript, use raw CDP when the user
grants it, and compose Android accessibility work without adding a gateway tool
for every gesture or application. The composition must still preserve the rule
that model output is a proposal and the owning surface is the executor.

## What Changes

- Define one versioned program envelope with two programs: a remote orchestrator
  program for gateway/execution-machine work and a local surface program.
- Reuse the gateway's existing agent harness for remote programs instead of
  introducing a second general-purpose runtime.
- Make the browser local language JavaScript/TypeScript. Execution profiles can
  grant tab APIs, DOM worlds, and named raw CDP domains including
  `Runtime.evaluate`.
- Make the Android local language a versioned declarative IR decoded and
  executed by native Java/Kotlin adapters over Accessibility and platform APIs.
- Require scope, grants, limits, lease, cancellation, approval state, program
  digest, and receipts for both programs and every surface effect.
- Define a future-surface matrix so macOS, Windows, and iOS choose a native
  program representation and runtime rather than inheriting browser semantics.

## Boundaries

- A broad execution profile is an explicit user/admin grant, not a property of
  being an agent or sharing a session.
- Raw CDP is supported, not silently enabled. Profiles name domains, origins,
  tabs/documents, worlds, duration, and whether state-changing methods require a
  checkpoint.
- Page content, accessibility content, and remote output remain untrusted
  evidence. They cannot widen the envelope.
- Browser programs never run as privileged extension source. Android does not
  evaluate generated Java/Kotlin source or load generated bytecode.
- Provider and integration credentials remain gateway-side. Browser session
  credentials remain browser-side and are not returned in receipts.
- Existing typed tools remain stable convenience and recovery primitives.

## Verification

- `openspec validate define-surface-program-runtime --strict`
- Contract tests for envelope validation, grant intersection, lease/cancel,
  receipt convergence, and forbidden authority widening.
- Browser fixture QA for JS/TS, raw CDP, background-tab lifecycle, and cancel.
- Android unit/instrumentation and phone QA for IR decoding, accessibility
  effects, stale state, approval, cancel, and receipts.

## Impact

- Gateway: program proposal/store, profile/grant resolution, remote-harness
  launch, lifecycle coordination, and receipt projection.
- Browser extension: isolated program runner, CDP broker, tab/document leases,
  local policy, cancellation, and receipts.
- Android: IR validator/interpreter over Accessibility and platform adapters,
  local approval, cancellation, and receipts.
- Future surfaces: an explicit adoption contract without pretending they are
  already implemented.
