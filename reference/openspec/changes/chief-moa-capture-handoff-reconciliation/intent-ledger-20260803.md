# Chief Moa Product Intent Ledger — 2026-08-03

## Scope And Authority

This ledger reconciles explicit Chief Moa intent only. It does not redefine
Branch Continue, Agent Switchboard, or Agent Launcher.

The latest user clarification supersedes any interpretation that turns Chief
Moa into the branching notebook or removes its responding assistant:

- **Branch Continue** owns branchy note-taking: leave a thought, capture a child
  thought, then return to the parent note.
- **Chief Moa** is the capture-from-any-Surface product. It preserves separate
  responding-assistant, literal-dictation, voice-note/intent-capture, and
  explicit execution/handoff paths.
- **Agent Switchboard** owns durable project and intent direction, ongoing
  context, agent steering, progress, and completion.
- **Agent Launcher** owns attachable execution sessions, not product intent.

Chief Moa and Switchboard may share stable intent, evidence, run, and artifact
identities. They must not silently become one product or grant one another
authority through shared storage.

The user's reflections about branchiness, closure, therapy, medication, family,
or books are source context, not automatically executable product tasks. Chief
Moa may preserve them only through the selected assistant/dictation/capture
path. Switchboard receives work only after explicit handoff.

## Stable Product Statement

From any supported Surface, the user can deliberately choose one of four
different outcomes:

1. **Assistant:** speak or type and receive the existing AI response.
2. **Dictation:** produce literal editable/copyable text with no reasoning,
   reply, tool, action, or agent launch.
3. **Voice note / intent capture:** preserve the original spoken source and an
   inspectable transcript or retryable failure, optionally bound to the app,
   page, selected element, or user-approved screen evidence. Capture alone does
   not answer or execute.
4. **Execute / hand off:** explicitly confirm a captured source or revision for
   Switchboard/work execution. The handoff returns stable intent/run identity
   and visible progress; it never derives action authority from screen content
   or model output.

Continuation is the default inside an existing assistant thread. A voice note
is not a Branch Continue branch, and uploading another segment must not silently
create a new intent or agent run.

## Acceptance Contract For The First Coherent Product Slice

On one supported Surface, the user deliberately selects **Capture**, records a
voice note, stops it, and receives a durable gateway receipt. After restarting
the client, the note appears newest-first and can be replayed. A transcription
failure leaves the audio recoverable and visibly retryable. Selecting **Hand
off** on that exact source creates or reuses one Switchboard-owned intent and
shows its stable external identity and progress. Merely capturing or replaying
the note creates no assistant reply, action proposal, tool request, or agent
run. The existing **Assistant** and **Dictation** actions still behave as
before.
